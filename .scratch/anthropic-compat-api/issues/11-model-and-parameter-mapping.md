# Model and parameter mapping

Type: grilling
Status: resolved
Blocked by: 02, 03

## Question

Which request fields does the surface honour, translate, ignore, or reject?

- **`model`**: accept full ids (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-4-5`, dated ids), aliases (`opus`, `sonnet`, `haiku`, `fable`), and what to do with unknown names (404 `not_found_error` like the real API, or pass through and let upstream decide). What `GET /v1/models` lists and whether it reports `max_input_tokens`, `max_tokens`, `capabilities`. **Collision**: the OpenAI surface already serves `GET /v1/models` in OpenAI shape (`app/src/api/routes/models.ts`); the Anthropic shape (`data[]` with `type: "model"`, `display_name`, `created_at`, `has_more`, `first_id`, `last_id`) differs. Per [Destination and target clients](01-destination-and-target-clients.md) the Anthropic approach wins; decide whether the OpenAI shape survives via header negotiation (`anthropic-version` present or not) or is dropped outright.
- **`max_tokens`**: required by the API but upstream has no equivalent. Validate presence and ignore? Never report `stop_reason: max_tokens`?
- **`temperature`, `top_p`, `top_k`, `stop_sequences`, `metadata`, `service_tier`**: ignore silently, warn via a header, or 400.
- **`thinking` and `output_config.effort`**: map to `--effort` (the only lever; bad values only warn); what to do with `budget_tokens`. Output side: upstream emits `thinking` blocks with empty text plus a signature and cannot disable thinking on Fable; decide whether to emit them empty (as the real API does with display omitted) or drop them, and whether to report thinking tokens in usage.
- **`output_config.format`**: map to `--json-schema`; upstream adds a `StructuredOutput` tool turn and returns the object in `result.structured_output`, which the surface would emit as a JSON text block.
- **Companion endpoints**: `GET /v1/models/{id}` (the real API resolves aliases there) and `POST /v1/messages/count_tokens`, which returns `{input_tokens}` but upstream can only report usage after a run: approximate, or answer 501/404.
- **`tool_choice`**: see the tool bridge ticket; which values 400.
- **`usage`**: use upstream's real `result.usage` token counts (input, output, cache) rather than the OpenAI surface's placeholder constants.
- **`stop_reason`**: `result.stop_reason` already uses `end_turn | tool_use | max_tokens | refusal`; decide how `subtype` (max turns, budget exceeded) and `is_error: true` (which can arrive with `subtype: "success"`, for example an unknown model) override it.

Record the table on this ticket.

## Facts from research

- `result` carries real per-turn `usage` and cumulative `modelUsage` (includes side calls and restored sessions); `total_cost_usd` is an estimate ([CLI contract](02-cli-headless-io-contract.md) §1). `--max-turns` exists despite `--help`; `--max-budget-usd` is checked only after the call that crosses it, so it cannot cap one response (§6, §7).
- The real API 400s on non-default `temperature`/`top_p`/`top_k` after Opus 4.6 and on `tool_choice: any|tool` for 5.x models, and `GET /v1/models` returns `{data, first_id, last_id, has_more}` with `max_input_tokens`, `max_tokens`, `capabilities` ([wire contract](03-messages-api-wire-contract.md) §1, §6).

## Decided in Tool bridge strategy (2026-10-04)

- `tool_choice` is settled: `auto`/absent default; `none` hides client tools from upstream for the turn; `any`/`tool` 400 with the real API's message on every model; `disable_parallel_tool_use` accepted and ignored. See [Tool bridge strategy](07-tool-bridge-strategy.md) decision 5. Keep the table here consistent with it.

## Decided in Conversation state and system prompt (2026-10-04)

- `--model` is passed on every run, including `--resume`, so the model may change mid-conversation without breaking a continued turn; `model` is not part of the fingerprint.
- `metadata.user_id` is accepted and ignored (not a session key). `cache_control` anywhere is accepted and ignored.
- Usage: per-turn numbers come from `message_delta.usage` / `result.usage`; `total_cost_usd` and `modelUsage` include totals restored on resume and must not be reported as the turn's. See [Conversation state and system prompt](10-conversation-state-and-system-prompt.md) decisions 3, 8, 10.

## Decided in Web search and built-in tools policy (2026-10-04)

`usage.server_tool_use.web_search_requests` = sum of `tool_use_result.searchCount` over the turn's WebSearch calls (fallback: count of WebSearch `tool_use` blocks); `web_fetch_requests` = count of WebFetch calls; Haiku side-call tokens are not reported. See [Web search and built-in tools policy](08-web-search-and-built-in-tools-policy.md) decision 8.

## Found in Residual upstream context (2026-10-04)

`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` in the child environment silently overrides `--model` with `claude-opus-5-5` (measured, `research/cli-probes/r6-*`). The wrapper must not set it, and the spec should require that the run's `system/init.model` equals the requested model, failing the turn otherwise. See [Residual upstream context and the account-email reminder](20-residual-upstream-context-and-account-email.md).

## Decided in Streaming fidelity (2026-10-07)

- `message_start.message.model` is this ticket's: the client's requested name echoed back, or upstream's actual model id as the `stream_event` carries it. Everything else in `message_start` is relayed from upstream's first model call.
- Thinking blocks are relayed exactly as upstream emits them (empty `thinking_delta`, one `signature_delta`), so a request's `thinking.display` has nothing to map to; `thinking_tokens` stays in `usage.output_tokens_details`.
- `stop_reason` is relayed verbatim from the final model call's `message_delta`, so `max_tokens`, `refusal` (with `stop_details`) and `stop_sequence` arrive as upstream reports them; this ticket decides only what request parameters reach upstream.
- The `usage` object is defined there (decision 6: field-wise sum of per-call `message_delta.usage` plus `server_tool_use` counts); this ticket adds nothing to it.

See [Streaming fidelity](09-streaming-fidelity.md) decisions 5, 6, 7.

## Answer

Resolved 2026-10-07 with the human, one grilling round of fourteen questions, every recommendation taken ("yes for all"). Each decision was checked against the SDK minimums in the [wire contract](03-messages-api-wire-contract.md) §8.1 to §8.4: none touches SSE framing, event order, `message_start` usage, `message_delta.usage.output_tokens` or `message_stop`; decision 9's prose-dropping rule exists to keep the SDK `parse()` helpers working, and the `/v1/models` listing returns `has_more: false` so `models.list()` terminates. One figure was sharpened while recording: decision 6's `output_tokens` for a stop-sequence cut is an estimate, because the interrupt aborts the call before upstream reports it. Recorded as [ADR 0004](../../../docs/adr/0004-output-limits-emulated-by-cutting-the-turn-stream.md). Vocabulary added to `GLOSSARY.md`: catalogue, run-bound parameter.

Facts new to this ticket, from seven probes run on 2.1.291 (`research/cli-probes/t1-*.jsonl` to `t7-*.jsonl`, scripts `t-run.py` and `t-run2.py`: the minimal-context method's flags plus `--no-session-persistence`, empty cwd, every `CLAUDE*` variable stripped from the environment; stderr empty on all seven):

- `CLAUDE_CODE_MAX_OUTPUT_TOKENS=<n>` caps every model call (`t1`, cap 100: four calls, each `message_delta {stop_reason: "max_tokens"}` with `output_tokens: 100`). Upstream then **auto-continues**: it injects a user message "Output token limit hit. Resume directly — no apology, no recap of what you were doing…" and makes another call, up to four in all, then emits an `assistant` frame with `message.model: "<synthetic>"`, `stop_reason: "stop_sequence"`, `stop_sequence: ""`, zero usage and the text "API Error: Claude's response exceeded the 100 output token maximum…", followed by `result {subtype: "success", is_error: true, num_turns: 4, stop_reason: "stop_sequence"}`, exit 1, 26 s wall. At a 300-token cap a WebSearch turn completed normally and the side call's `tool_result` (1,883 characters) was not truncated (`t7`).
- `--model sonnet` resolves **before** the API call: `system/init.model` and `message_start.message.model` both read `claude-sonnet-5-5` (`t2`); `--model haiku` resolves to the dated `claude-haiku-4-5-20251001` (`t4`). `system/init` carries no `effort` field even with `--effort low` (`t2`), so the applied effort cannot be verified from frames.
- `--json-schema` with partial messages (`t3`): `content_block_start {tool_use, name: "StructuredOutput", input: {}}` → `input_json_delta` chunks (`""`, `{"word": "pong`, `"}`) → `content_block_stop` → a `user` frame whose `tool_result` reads "Structured output provided successfully" → **that same call's** `message_delta {stop_reason: "tool_use", output_tokens: 52}` and `message_stop` → `result {structured_output: {"word": "pong"}, num_turns: 2}`. No further model call. `init.tools` is `["StructuredOutput"]` despite `--tools ""`.
- Haiku 4.5 **thinks by default** under upstream (`t4`: thinking block, `thinking_tokens: 123`), where the real API's Haiku default is no thinking. `CLAUDE_CODE_DISABLE_THINKING=1` removes the block and reports `thinking_tokens: 0` (`t5`). `MAX_THINKING_TOKENS=1024` ran normally with 132 thinking tokens (`t6`): accepted, effect under a binding budget unobserved.
- `strings` over the 2.1.291 binary lists these model-affecting variables: `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_{FABLE,OPUS,SONNET,HAIKU}_MODEL` (and `_NAME`, `_DESCRIPTION`, `_SUPPORTED_CAPABILITIES`), `ANTHROPIC_SMALL_FAST_MODEL`, `CLAUDE_CODE_EFFORT_LEVEL`, `CLAUDE_CODE_ALWAYS_ENABLE_EFFORT`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `MAX_THINKING_TOKENS`, `CLAUDE_CODE_DISABLE_THINKING`, `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING`, `CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `CLAUDE_CODE_NO_MODEL_FALLBACK`, `CLAUDE_CODE_DISABLE_MODEL_ACCESS_FALLBACK`, `CLAUDE_CODE_MODEL_CATALOG`, `CLAUDE_CODE_MODEL_CATALOG_URL`, `CLAUDE_CODE_MAX_CONTEXT_TOKENS`, `CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_CODE_THINKING_DISPLAY_UPDATES`.
- `ModelInfo.capabilities` sub-shapes (`../spike/node_modules/@anthropic-ai/sdk/resources/models.d.ts`): every capability is `{supported: boolean}`; `effort` adds `low`, `medium`, `high`, `max` as `{supported}` and `xhigh` as `{supported} | null`; `context_management` adds `clear_thinking_20251015`, `clear_tool_uses_20250919`, `compact_20260112` as `{supported} | null`; `thinking` is `{supported, types: {adaptive: {supported}, enabled: {supported}}}`. `capabilities` itself may be `null`.
- The OpenAI surface's `GET /v1/models` (`app/src/api/routes/models.ts`) returns `{object: "list", data: [{id: "sonnet"}, {id: "opus"}]}` with OpenAI fields and no retrieve route.

### Decisions

| # | Decision |
| - | - |
| 1 | **Catalogue.** A JSON file shipped with the wrapper, at an operator-overridable path, holds one entry per served model in `ModelInfo` shape plus `aliases[]`. First content: `claude-fable-5-1` (alias `fable`), `claude-opus-5-5` (`opus`), `claude-sonnet-5-5` (`sonnet`), `claude-haiku-4-5-20251001` (`haiku`, `claude-haiku-4-5`). A request's `model` must resolve to an entry by id or alias, else 404 `not_found_error` with the real API's message `model: <name>` before any spawn. The entry's canonical id is what `--model` receives, never the client's alias; `system/init.model` must equal it or the turn fails (the requirement from [Residual upstream context](20-residual-upstream-context-and-account-email.md)); `message.model` in `message_start` relays upstream's value, which is the resolved id (`t2`, `t4`). Upstream's own 404 (`result.api_error_status: 404`) remains as the backstop for a catalogued model the login cannot use. CLI-only aliases (`default`, `best`, `opusplan`, `sonnet[1m]`, `opus[1m]`) are not in the catalogue unless an operator adds them. |
| 2 | **`GET /v1/models` collision: negotiate on `anthropic-version`.** Header present → the Anthropic shape `{data: ModelInfo[] (newest first), first_id, last_id, has_more: false}`, with `limit`, `after_id`, `before_id` applied over the catalogue; header absent → today's OpenAI handler, untouched, hard-coded entries included (reworking the OpenAI surface is out of scope). `GET /v1/models/{id}` is Anthropic-only: with the header, id or alias → the entry under its canonical id, else 404 `not_found_error`; without the header the path stays unserved as today. Neither official SDK regresses: the Anthropic SDKs always send the header, the OpenAI SDK never does. |
| 3 | **`ModelInfo` content.** `id`, `type: "model"`, `display_name`, `created_at`, `max_input_tokens` and `max_tokens` copied from the real API's `GET /v1/models` at implementation time (`null` where unsourceable). `capabilities` is **honest to the surface**: `batch`, `code_execution`, `context_management` (and its three dated keys) and `citations` unsupported; `image_input`, `pdf_input`, `structured_outputs` supported; `effort` and `thinking` as the real API reports them for that model. The catalogue is also the source for every per-model validation below. |
| 4 | **`max_tokens` is honoured.** Validation before spawn: integer, ≥ 1, ≤ the entry's `max_tokens`, else 400 `invalid_request_error` naming the range; `0` (the real API's cache pre-warm) is 400. The run's child environment carries `CLAUDE_CODE_MAX_OUTPUT_TOKENS=<max_tokens>`. **Cut rule**: when a relayed model call's `message_delta` carries `stop_reason: "max_tokens"`, the translator relays that `message_delta` and `message_stop` (the real API's exact shape: partial content, `output_tokens` = the cap), closes the response, sends `control_request interrupt` so upstream does not auto-continue, and forgets the upstream session (the next turn is a replayed turn, as after a post-commit error in [Streaming fidelity](09-streaming-fidelity.md) decision 10). Frames after the cut are ignored. Documented deviations: the cap applies per model call, so a multi-call turn (built-in tools) can emit more than `max_tokens` in total; the interrupt can lose the race against upstream's next call, costing at most one more capped call. |
| 5 | **Sampling parameters.** On every catalogue model: `temperature` absent or `1.0`, `top_p` absent or ≥ `0.99`, `top_k` absent; anything else is 400 `invalid_request_error` naming the field and the accepted value. Stricter than the real API on Haiku 4.5, deliberately: upstream has no knob, and silently accepting `temperature: 0` would misreport what ran. |
| 6 | **`stop_sequences` are emulated.** Validated as a non-empty array of non-empty strings. The translator scans `text_delta` payloads only (thinking, tool and server-tool blocks untouched), holding back up to `len(longest sequence) - 1` characters so a match split across deltas is still found, and flushing the hold-back at `content_block_stop`. On a match it relays the text before the match, closes the open block, emits `message_delta {stop_reason: "stop_sequence", stop_sequence: <matched>}` and `message_stop`, closes the response, interrupts and forgets the session (decision 4's path). Usage in that `message_delta`: input and cache counters from the current call's `message_start` plus earlier calls' sums; `output_tokens` for the cut call is an **estimate** (the call's own `message_start.usage.output_tokens` plus the relayed characters divided by four), because the interrupt aborts the call before upstream reports it. This is the one inexact usage figure on the surface and the spec says so. |
| 7 | **`thinking`.** Catalogue-driven, mirroring the real API's acceptance per model, and the request's `display` is ignored (upstream always omits thinking text; Streaming fidelity decision 5 relays the empty blocks). 5.x entries: `adaptive` accepted with nothing to pass; `enabled`, `disabled` and `between_tools` 400 with the real API's messages. Haiku 4.5 entry: absent or `disabled` → `CLAUDE_CODE_DISABLE_THINKING=1` in the child environment (verified, `t5`; needed because upstream thinks by default where the real API does not), `enabled` → `MAX_THINKING_TOKENS=<budget_tokens>` after the real API's checks (`budget_tokens` integer ≥ 1024 and < `max_tokens`, else 400), `adaptive` and `between_tools` 400. The effect of `MAX_THINKING_TOKENS` under a binding budget is **unverified** (`t6` did not bind) and is listed on the map's test-strategy fog. |
| 8 | **`output_config.effort`** passes verbatim as `--effort <level>`. Validation before spawn: one of `low`, `medium`, `high`, `xhigh`, `max`, and supported by the entry's `effort` capability, else 400; so upstream's warn-and-ignore never triggers. Absent → no flag, upstream's default. The child environment never carries `CLAUDE_EFFORT` or `CLAUDE_CODE_EFFORT_LEVEL`. Not verifiable from frames (`init` has no `effort`). |
| 9 | **`output_config.format` maps to `--json-schema`.** `format.type` must be `json_schema`; `schema` is passed verbatim (the CLI validates it at startup; its stderr rejection is a pre-commit 400 per Streaming fidelity decision 10). Translator rule: a `tool_use` block named `StructuredOutput` is **buffered** (start, `input_json_delta`s, stop) until its synthetic `tool_result` frame arrives, which precedes that call's `message_delta`. On success the buffer is emitted as one `text` block whose `text_delta`s are the buffered `partial_json` chunks (empty chunks skipped), that call's `stop_reason: "tool_use"` is rewritten to `"end_turn"`, and the turn closes on its `message_delta`/`message_stop`. On a validation failure (`tool_result` with `is_error`) the call is treated like a built-in tool call: buffer dropped, `message_delta`/`message_stop` suppressed, the retry call follows; `result {subtype: "error_max_structured_output_retries"}` is a post-commit error. Prose `text` blocks in a format run are dropped and logged, because both SDKs' `parse()` helpers require every text block to be JSON. A `max_tokens` cut inside a buffered block flushes the buffer as the text block first. Non-streaming accumulates the same text; `result.structured_output` is not used. The child environment never sets `CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS`. |
| 10 | **Run-bound parameters on a resuming turn are ignored.** `model`, `max_tokens`, `thinking`, `output_config.effort`, `output_config.format` and `system` are fixed when upstream is spawned, so the turn that resumes a parked run cannot change them: differing values are ignored and logged at debug, in the spirit of [Tool bridge strategy](07-tool-bridge-strategy.md) decision 11. `message.model` relays upstream's actual model, so the client is never misled about which model answered. `stop_sequences` are not run-bound (emulated per turn). |
| 11 | **`POST /v1/messages/count_tokens` measures.** The request goes through the normal validation (decisions 1, 4 to 9, 12; `tool_choice` `any`/`tool` 400 as on Messages) and translation (system prompt, rendered history, mounted tools), spawned with `CLAUDE_CODE_MAX_OUTPUT_TOKENS=1` and no session persistence. The surface reads the first `message_delta`, interrupts, keeps no fingerprint entry, and answers `{input_tokens: input_tokens + cache_creation_input_tokens + cache_read_input_tokens}` from that `message_delta.usage`. Exact for what upstream actually sends, which includes the residual context (about 500 tokens on `--system-prompt ""`, [Minimal-context upstream run](16-minimal-context-upstream-run.md)) and the replayed-turn rendering; documented. Cost: one minimal model call per count, which also warms the cache for the request that usually follows. Pre-commit failures are HTTP statuses as on Messages. |
| 12 | **Remaining body fields.** Accepted and ignored: `service_tier` (enum `auto`/`standard_only` validated; `usage.service_tier` relays upstream's value), `inference_geo` (`usage.inference_geo` relays upstream's, observed `not_available`), `diagnostics` (response `diagnostics: null`), plus the already-decided `metadata` and `cache_control` ([Conversation state](10-conversation-state-and-system-prompt.md)). 400 `invalid_request_error`: `container` (no containers on this surface, own message); any unknown top-level field and every beta-only body field (`context_management`, `speed`, `fallbacks`, `output_format`, `output_config.task_budget`) with the real API's "Extra inputs are not permitted" wording (ticket 12 confirms exact texts). `mcp_servers` is [MCP connector passthrough](15-mcp-connector-passthrough.md)'s; `betas` and the `anthropic-beta` header are [Error envelope and auth headers](12-error-envelope-and-auth.md)'s. |
| 13 | **Flags and environment never used.** `--fallback-model` never (a silent model switch would contradict `message.model`); `--max-budget-usd` never (checked after the call that crosses it, and it zeroes `usage`). `--max-turns` belongs to [Process lifecycle](19-process-lifecycle-and-concurrency.md) as a runaway guard. The child environment is an allowlist built from scratch (ticket 19 owns the base); the model-affecting variables listed in the facts are set only as decisions 4, 7, 8, 9 and 11 dictate. |
| 14 | **`result` never overrides a relayed `stop_reason`.** It is consulted only on the error paths of Streaming fidelity decision 10 and, for `count_tokens`, not at all. Hygiene rule added to the translator: an `assistant` frame whose `message.model` is `"<synthetic>"` is upstream's error prose (`t1`, and in the earlier `p4-bare`, `r1-simple-env`, `o-pass-through-run*` recordings) and is dropped, never relayed as content; the status and error type come from `result` via ticket 12. |
