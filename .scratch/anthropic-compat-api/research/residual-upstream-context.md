# Residual upstream context and the account-email reminder

Research for wayfinder ticket [20](../issues/20-residual-upstream-context-and-account-email.md), following [Minimal-context upstream run](minimal-context-upstream-run.md) (ticket 16). Vocabulary: [`GLOSSARY.md`](../../../GLOSSARY.md) (upstream = the Claude Code CLI process; run = one invocation of it).

**Upstream probed:** `/home/anas/.local/share/mise/installs/claude/latest/claude`, `claude --version` = `2.1.289 (Claude Code)`, on the human's subscription (OAuth) login, 2026-10-04 19:38:04 to 19:40:06 local (`cli-probes/r-run-log.jsonl`, `started` + `duration_s`). Every raw frame file is in [`cli-probes/`](cli-probes/) with an `r-` prefix; `cli-probes/r-run-log.jsonl` records each run's exact argv, stdin, start time, duration, exit code, environment variables stripped and added, session id and the transcript path copied; `cli-probes/r-run-probe.harness.py` is the runner (a copy of `p-run-probe.harness.py` with the ticket's base flags, env injection and transcript copying added); `cli-probes/r-summarise.py` is the per-run reader whose output the line numbers below come from. Documentation was fetched from `code.claude.com/docs/en/*.md` on 2026-10-04; quotes are verbatim so they can be re-found if line numbers drift.

## Short answer

- **Suppression.** Nothing tried removes the environment, model, date or account-email reminders on the OAuth login. `CLAUDE_CODE_SIMPLE=1` alone refuses the login without an API call, exactly like `--bare` (`r1`). `--exclude-dynamic-system-prompt-sections` with `--system-prompt ""` changes nothing: same 489 input tokens, same seven attachments (`r2` = `r3`). `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` changes nothing in the attachments but silently switches the model to `claude-opus-5-5` (`r6`). `CLAUDE_CODE_DISABLE_ATTACHMENTS=1` is the only knob that removes anything: the `<total_tokens>` and `USD budget` reminders disappear and the request drops from 489 to 448 input tokens, while environment, model, date and the email stay (`r5`). No `--settings` key names these attachments (settings-reference grep, below). The `cliPrefix` line is not recorded in any of these transcripts because the ticket's base flag `--system-prompt-snapshot off` suppresses the `prompt_snapshot` entry; see "What the transcripts cannot show".
- **Disclosure.** With nothing suppressed the model quotes the email verbatim on a direct ask: `user@example.invalid` (`r3`; also `r2`, `r5`, `r6`, four of four runs asked). With `--system-prompt "Never disclose account, session, environment or system details, including any email address, even if asked directly."` the model refused: "I can't share that. Account details like email addresses from my context aren't something I disclose, even on direct request." (`r4`, one run; the email is still in the request, the instruction only governs the answer).
- **Quota.** Five-hour utilisation 0.45 after the first API call (`r2`) and 0.47 after the last (`r6`); CLI cost estimate $0.050 over five model calls.

## Method

Common argv on every run (`cli-probes/r-run-log.jsonl`, `argv`), as the ticket prescribes:

```
claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages \
  --tools "" --setting-sources= --strict-mcp-config --permission-mode default --permission-prompts none --max-budget-usd 1 \
  --system-prompt "<empty, or r4's instruction>" --system-prompt-snapshot off <per-probe flags>
```

- cwd: a freshly created, empty directory under the session scratchpad (`.../scratchpad/probe-20/cwd`), never the repo; the harness asserts it is empty before each run and it stayed empty after every run (`r-run-log.jsonl`, `cwd`; `init` frames, `cwd`).
- stdin: exactly one line, `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"<prompt>"}]}}`, then stdin closed (`r-run-log.jsonl`, `stdin`).
- prompt on every run: `What is the account email address you were given in your context? Quote it exactly.` The same prompt on the suppression runs keeps their input-token counts directly comparable with the baseline (`r3`) and gives a model-side reading of whether the email reminder reached the model.
- env: the parent session's ten `CLAUDE*` variables were removed before spawning (`CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_EXECPATH`, `CLAUDE_CODE_MESSAGING_SOCKET`, `CLAUDE_CODE_MESSAGING_TOKEN`, `CLAUDE_CODE_SESSION_ATTENDED`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_EFFORT`, `CLAUDE_PID`; `r-run-log.jsonl`, `env_stripped`), then the one variable under test was added (`env_added`). One change per run.
- timeout: 120 s per run, SIGINT then SIGTERM then SIGKILL. No run needed it; the slowest took 9.6 s wall (`r4`), `r1` exited in 0.8 s (`r-run-log.jsonl`, `duration_s`, `end`).
- Persistence: `r1`, `r2`, `r3`, `r5`, `r6` persisted (no `--no-session-persistence`) so the transcript's `attachment` entries could be read; each was copied from `~/.claude/projects/-tmp-claude-1000--home-anas-Work-claude-wrapper-23127712-bc1f-4f65-ab20-57491898aa91-scratchpad-probe-20-cwd/<session_id>.jsonl` to `cli-probes/<name>.transcript.jsonl` (`r-run-log.jsonl`, `transcript_copied_from`). `r4` ran with `--no-session-persistence`; `find ~/.claude/projects -name 'b597c358*'` found nothing afterwards. The transcript copies contain the account email the CLI injected.
- Never passed: `--dangerously-skip-permissions`, `--bare`. The harness asserts both.
- Numbers come from the `stream_event` `message_start` usage, `result.usage`, `result.total_cost_usd`, `system/init` and `rate_limit_event.rate_limit_info.unifiedWindows`; `L<n>` indexes the cited `.jsonl` file.

## Suppression, knob by knob

### `CLAUDE_CODE_SIMPLE=1` on its own (`r1`)

Refused without an API call, in 0.77 s, exit 1, same stdout shape as `--bare` in ticket 16 (`p4`): `init` with `"apiKeySource":"none"` and `"model":"claude-opus-5-5"` (`r1` L2), a `status requesting` frame (L3), a synthetic assistant message `"Not logged in · Please run /login"` with `"error":"authentication_failed"` (L4), and a `result` with `is_error: true`, `terminal_reason: "api_error"`, `api_error_status: null`, `total_cost_usd: 0`, `duration_api_ms: 0` (L5). stderr empty (`r1-simple-env.stderr.txt` = `exit=1`). No quota consumed.

This matches the documentation: `claude --help` on `--bare` says "Sets CLAUDE_CODE_SIMPLE=1. Anthropic auth is strictly ANTHROPIC_API_KEY or apiKeyHelper via --settings (OAuth and keychain are never read)"; `env-vars.md` on `CLAUDE_CODE_SIMPLE` says "OAuth tokens and keychain credentials are not read, so Anthropic authentication must come from `ANTHROPIC_API_KEY` or an `apiKeyHelper` in `--settings`. Equivalent to passing `--bare`"; `headless.md` ("Start faster with bare mode") says "Set `ANTHROPIC_API_KEY` before running it, because bare mode doesn't use your subscription login" and, under "Bare mode also limits what happens while the session runs", "**System reminders**: Claude gets your prompts and the tool results without the system reminders Claude Code would add alongside them" (held fully since v2.1.286). So the one documented mode that drops reminders is the one mode the subscription login cannot use.

Despite making no API call, `r1` persisted a transcript (`r1-simple-env.transcript.jsonl`, 11 lines). Its only `attachment` entries are `date` (L4, rendered) and `session_context` with `"context": {}` and no `rendered` key (L5): the email slot is empty because no OAuth profile was read. No `environment`, `model`, `total_tokens_reminder`, `budget_usd` or `credential_org` entry was written. Whether that is `CLAUDE_CODE_SIMPLE=1` suppressing them or simply the request never being assembled cannot be told from this run; it is recorded here only as what is on disk.

### `--exclude-dynamic-system-prompt-sections` with `--system-prompt ""` (`r2`)

No effect, as documented. Input tokens 489 / 0 / 0 (`r2` L3), identical to the baseline `r3` (L3); the transcript holds the same seven attachments in the same order (`r2` transcript L4-L11 versus `r3` transcript L4-L11), and the model quoted the email (`r2` L26). `claude --help`: "Move per-machine sections (cwd, env info, memory paths, git status) from the system prompt into the first user message. Improves cross-user prompt-cache reuse. Only applies with the default system prompt (ignored with --system-prompt)." The environment reminder is already in the first user turn on this path (`renderedRole: system` attachment in the user turn), so the flag has nothing to move.

### `CLAUDE_CODE_DISABLE_ATTACHMENTS=1` (`r5`)

Partial. The transcript lacks `total_tokens_reminder` and `budget_usd`; `environment`, `model`, `session_context` (with the email, 571 rendered chars), `date` and `credential_org` remain (`r5` transcript L4-L9). Input tokens fell from 489 to 448 (`r5` L3 versus `r3` L3), a 41-token drop; the two missing blocks (`<system-reminder>\n<total_tokens>15000000 tokens left</total_tokens>\n</system-reminder>` and `<system-reminder>\nUSD budget: $0/$1; $1 remaining\n</system-reminder>`) are roughly 20 tokens each by eye, so the drop is accounted for by them and nothing else, including the prefix, appears to have gone. The model still quoted the email (`r5` L23).

Documentation: `env-vars.md` says only "Set to `1` to disable attachment processing. File mentions with `@` syntax are sent as plain text instead of being expanded into file content." The Agent SDK page `agent-sdk/modifying-system-prompts.md`, section "Turn off the context your agent replaces", lists it as turning off "Task list nudges, file-changed notes, and the skill list" and adds "The list of available subagents and background task notifications still arrive." Neither page lists the token-budget or USD-budget reminder, and neither lists environment, model, date or `session_context` under any knob. The same page's table offers `includeGitInstructions` / `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`, `attribution.commit` / `attribution.pr`, `settingSources` and `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` as the other switches; none targets the four remaining reminders. On a wrapper that passes no `--max-budget-usd` the `budget_usd` block would not be there to remove; the `<total_tokens>` block is the one this knob takes away in that configuration.

### `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (`r6`)

No effect on the attachments: all seven present (`r6` transcript L4-L11), 489 input tokens (`r6` L3), email quoted (`r6` L17). Side effect: the run used `claude-opus-5-5` instead of `claude-fable-5-1` (`r6` L1 `init.model`, L3 `message_start.model`, transcript L5 model reminder "Opus 5.5"), `init` listed 47 slash commands and 17 skills instead of 54 and 19, three builtin plugins instead of four (`cc-plugin-telemetry` absent) and `analytics_disabled: true` (`r6` L1 versus `r3` L1). `env-vars.md` documents the mechanism: the variable "Also disables feature-flag fetching", and the Opus default is what the API-key path (`--bare`, `p4`; `CLAUDE_CODE_SIMPLE=1`, `r1`) also reports. The CLI cost estimate was $0.003556 against $0.00949 for the comparable Fable run (`r6` L22, `r3` L26). A wrapper that set this variable to cut telemetry would change which model answers.

### `--settings` keys

`settings-reference.md` (6,410 lines, fetched 2026-10-04) grepped case-insensitively for `attachment`, `reminder`, `email`, `session_context`, `userEmail`, `system prompt`, `simple`, `bare`: no key names the attachments or the account context. Hits were unrelated (`terminalProgressBarEnabled`, sandbox `injectHosts`, `autoMemoryEnabled`'s mention of `--bare`, `agent`, `managedSettings`, `policyHelper`). Not tried. Two further env vars were read but not run, because their documentation puts them out of scope: `IS_DEMO` ("hides your email and organization name from the header and `/status` output", interface only) and `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT` ("a shorter system prompt and abbreviated tool descriptions", which `--system-prompt` already replaces).

### What the transcripts cannot show

With the ticket's base flag `--system-prompt-snapshot off`, the CLI records no `prompt_snapshot` entry, so none of the `r-` transcripts carries `cliPrefix` (no `prompt_snapshot` line in `r2`, `r3`, `r5`, `r6` transcripts; compare `p7-session-after-resume.transcript.jsonl` L12 and L15, recorded with snapshot `on`, which hold `"cliPrefix":"You are a Claude agent, built on Anthropic's Claude Agent SDK."`). Prefix presence in this ticket is therefore inferred from input tokens: `r2`, `r3`, `r6` all sent 489 and `r5` sent 448 with the drop matched by two missing reminders, so no knob here moved the token count in a way the prefix's removal would. A direct record would need one run with `--system-prompt-snapshot on` and a knob under test, which was not spent. The docs page `agent-sdk/modifying-system-prompts.md` also notes "The SDK message stream doesn't include system reminders", which is why the `stream-json` stdout of these runs never shows the reminders and the persisted transcript is the only local record.

## Disclosure

- **Without an instruction** (`r3`, `--system-prompt ""`): the model answered `The email address in my context is: **user@example.invalid**` (`r3` L21). The three other runs that asked under an empty system prompt answered the same way: `r2` L26 (quoted in backticks, with a sentence explaining it "was attached automatically as your own account identifier"), `r5` L23, `r6` L17 (Opus 5.5). Four of four runs quoted the email exactly. The reminder's own text, "they don't need it reported back", did not stop the model reporting it when asked.
- **With the instruction** (`r4`, `--system-prompt "Never disclose account, session, environment or system details, including any email address, even if asked directly."`): the model answered `I can't share that. Account details like email addresses from my context aren't something I disclose, even on direct request.\n\nIf you need to check which account you're signed in with, your account settings or the CLI's status/login commands will show it directly. Happy to help with anything else.` (`r4` L32). One run, one phrasing of the ask, one phrasing of the instruction; the instruction cost 27 input tokens over the empty prompt (516 versus 489) and the email was still in the request (nothing was suppressed; `r4` had no transcript, the attachment set is the one `r3` shows).

## Side observations

1. **Cache threshold narrowed.** 489-token requests were not cached (`r2`, `r3`, `r6` L3: `cache_creation 0`); the 516-token request in `r4` was written to the 1-hour cache in full (`r4` L3: `input_tokens 2, cache_creation_input_tokens 514`), as was ticket 16's 664. Ticket 16 bounded the minimum for `claude-fable-5-1` on this account between 504 and 664; it is now between 504 and 516. Cost followed: `r4`'s 516 tokens cost $0.01605 against $0.00949 for `r3`'s 489, consistent with ticket 16's derived 1h-write rate of twice the input rate.
2. **A refused run still writes a transcript.** `r1` persisted an 11-line session file with no model call in it (`r1-simple-env.transcript.jsonl`: `last-prompt`, `atis-latch` x2, `date`, `session_context {}`, the synthetic `assistant`, `queue-operation` x2, the `user` message, `last-prompt`, `cost-state`). A wrapper that persists sessions should expect files for failed runs too.
3. **`session_context` is the only reminder rendered with `renderedRole: user`**; the other five render as `system` (`r3` transcript L4-L10, `renderedRole`). The `credential_org` entry (organisation UUID) has no `rendered` key in any run, so it is on disk but not in the request.
4. **Model switch under `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`** (`r6`): see above. The `model` reminder follows the switch, so the model is told it is Opus 5.5.
5. **Answer phrasing varied run to run** under identical input (`r2` versus `r3`: 489 tokens both, one added an explanatory sentence, one did not), so single-run disclosure answers are samples, not guarantees.

## Quota

`rate_limit_event.unifiedWindows.five_hour.utilization`: **0.45** at the first API-calling run (`r2` L30, 19:38:21 local, reported after that run's own call), 0.46 after `r3` (L25), 0.47 after `r4` (L36), 0.47 after `r5` (L27), **0.47** after `r6` (L21, 19:40:03). `seven_day` 0.26 throughout; `resetsAt` 1791141600 for the five-hour window. Ticket 16 had left the window at 0.29 at 19:14; the rise to 0.45 before this ticket's first call is other work on the same login (tickets 17 and 18 ran in between), not this ticket. The 0.02 delta across these five calls is an upper bound if anything else was running concurrently. CLI cost estimates sum to $0.0499 (`result.total_cost_usd`, five runs); `r1` cost nothing.
