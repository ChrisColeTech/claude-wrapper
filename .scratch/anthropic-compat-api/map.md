# Map: Anthropic surface for claude-wrapper

Label: wayfinder:map
Created: 2026-10-04
Driver: anaslaham
Closed: 2026-10-07, spec at [spec.md](spec.md)

## Destination

An implementation-ready spec at `.scratch/anthropic-compat-api/spec.md` for an **Anthropic surface** on claude-wrapper: `POST /v1/messages` (non-streaming and SSE streaming) plus its companion endpoints, served alongside the existing OpenAI surface and fulfilled by the upstream Claude Code CLI, with every design decision locked for client tools, web search, streaming, conversation state, model and parameter mapping, and error and auth mapping. Where the two surfaces collide (same path or shared middleware with different wire shapes), the Anthropic approach wins. The map is done when `/to-spec` can write that spec with nothing left to decide. Building it is a separate effort.

## Notes

- **Domain**: TypeScript/Express server in `app/` (Node >=18, Jest, strict TS). Project standards in `docs/architecture/ARCHITECTURE.md` (SOLID, files <200 lines, functions <50 lines, constants not magic values). Upstream is driven today by `exec` + `echo | claude --print` in `app/src/core/claude-resolver.ts`; the OpenAI surface asks the model to emit OpenAI JSON via a prompt template and simulates streaming by chunking a finished answer.
- **Installed upstream**: Claude Code 2.1.291 at `~/.local/share/mise/installs/claude/latest/claude` (2026-10-07; the research on 2026-10-04 ran on 2.1.284 and 2.1.289; mise `latest` moves between sessions, so re-check `claude --version` each session). Full flag list: `claude --help`.
- **Skills every session should consult**: `claude-api` (the Messages API wire shapes to emulate; ignore its "call the API through the SDK" rule, this project drives the CLI on purpose), `domain-modeling` (vocabulary lives in `GLOSSARY.md`), `codebase-design` when a ticket touches module seams.
- **Standing preferences** (confirmed 2026-10-04 in [Destination and target clients](issues/01-destination-and-target-clients.md)): additive, the OpenAI surface keeps working, but on any collision the Anthropic approach wins; maximise feature coverage, web search and client tools named explicitly; fidelity over convenience, the official TypeScript and Python SDKs must work unmodified against the surface; the surface is a pure model endpoint, never a host-side agent.
- **Auth model (fact, 2026-10-04)**: upstream runs on the CLI's own login; a probe reported `apiKeySource: "none"`, i.e. the subscription OAuth login. Anthropic's legal page says developers should use API-key authentication and OAuth is for ordinary use of Claude Code, while a support article says SDK and `-p` use still draws on subscription limits. Details and citations in `research/agent-sdk-and-control-protocol.md` §6. Since late September 2026 some wrappers receive a server-side 400 "Third-party apps now draw from extra usage", which users bisected to appended system-prompt content (see `research/prior-art.md`, pitfalls). Not a decision on this map; the human owns the stance.
- **Research assets** live at `.scratch/anthropic-compat-api/research/<name>.md` (this tracker's scratch space, not a `research/*` branch) and are linked from the ticket that commissioned them.
- **Vocabulary**: use `GLOSSARY.md` terms (surface, upstream, turn, run, client tool, built-in tool, server tool, tool bridge, bridge server, held-open run, park, pre-delivered result, upstream session vs wrapper session, fingerprint, continued turn, replayed turn).

- [Anthropic Messages API wire contract](issues/03-messages-api-wire-contract.md): SDKs are strict on shape and event order, lenient on fields; `model`/`messages`/`max_tokens` required; `anthropic-version` required, auth via `x-api-key` or Bearer; streaming must emit `message_start` (empty content, usage), contiguous block indices, `message_delta` with usage, `message_stop`; error envelope `{type:"error", error:{type,message}, request_id}`; web search appears as `server_tool_use` + `web_search_tool_result` + citations; `tool_choice: any|tool` 400s on 5.x models. Full findings in `research/messages-api-wire-contract.md`.
- [Agent SDK and the stream-json control protocol](issues/04-agent-sdk-and-control-protocol.md): the SDK spawns `claude --output-format stream-json --input-format stream-json --verbose` and speaks NDJSON over stdio; it can be pointed at the mise-installed binary; in-process tools are announced in the `initialize` control request and each call arrives as a `control_request` `mcp_message` carrying the assistant `tool_use` id, answered by a `control_response`; a handler may block for hours (no SDK deadline, CLI MCP timeout defaults to ~28 h), stdin held open keeps the run alive between turns; built-in tool calls and results are visible as frames and hooks; raw API `stream_event`s available. Full findings in `research/agent-sdk-and-control-protocol.md`.
- [Prior art: Anthropic surfaces over Claude Code](issues/05-prior-art.md): real client-tool round trips have been solved three times, all on OpenAI surfaces, all by holding the run open with the Agent SDK's in-process MCP tool whose handler awaits the next HTTP request; nobody has done it on `/v1/messages` or over the raw CLI (those projects end the run and replay history as prose). Verbatim `stream_event` to Anthropic SSE passthrough is proven. Lessons: key pending calls on upstream `toolu_` ids, pass JSON Schema verbatim (Zod conversions broke four projects), disable built-ins when client tools are present, use the `mcp__` prefix to tell client calls (park) from built-ins like WebSearch (continue), add TTL and stall watchdog. Full findings in `research/prior-art.md`.
- [Claude Code CLI headless I/O contract](issues/02-cli-headless-io-contract.md): `assistant` lines are real Anthropic Messages but one line per content block with `stop_reason: null` (group by `message.id`, take `stop_reason`/`usage` from `message_delta` or `result`, strip non-API extras); `stream_event.event` is the raw API event stream, relayable almost verbatim; WebSearch is a built-in `WebSearch` tool_use with title+url results only (no citations, no `encrypted_content`); stdin can be held open with per-turn `result`s and image input, but a bare `tool_result` on stdin is silently dropped, so the tool bridge must be MCP or re-runs; `result` carries real usage, `api_error_status`, `structured_output`; `--system-prompt` removes only ~4k of a ~20k-token default context and forces a cache miss, `--append-system-prompt` is cheap; wrapper-minted `--session-id` UUIDs and `--resume` work; thinking arrives empty with a signature. 18 raw probe transcripts in `research/cli-probes/`. Full findings in `research/cli-headless-io-contract.md`.
- [Spike: round-trip one client tool call through upstream](issues/06-spike-client-tool-round-trip.md): **yes, on both drivers** (Agent SDK in-process MCP tool; raw `claude -p` + `--mcp-config` to a wrapper-hosted HTTP MCP server). Upstream's `tool_use.id` = MCP `_meta claudecode/toolUseId` = `tool_result.tool_use_id`, so no id minting; bridge overhead ≤ 9 ms each way; upstream's own `message_delta(tool_use)` and `message_stop` arrive while parked. Upstream runs one message's `tool_use` blocks one at a time, so park on message completion and hold pre-delivered results. Abandon by **interrupt first** (0 extra model calls; a raw `control_request` on stdin works without the SDK); MCP timeout or stdin EOF while parked cost 2 to 3 extra model calls. Hybrid `--resume` works but delivers the result as prose. SDK run context ~2k tokens vs ~10k raw (SDK sends an empty system prompt). Primary source in `spike/`.
- [Tool bridge strategy](issues/07-tool-bridge-strategy.md): **held-open run** through a wrapper-hosted bridge server (`mcp__client__<name>`), driver deferred to Module layout; correlation by upstream's `tool_use` ids only; park on message completion with pre-delivered results; partial answers 400; `tool_choice` `any`/`tool` 400, `none` hides the tools, `disable_parallel_tool_use` ignored; park TTL 10 min default, interrupt-then-reject, a lost park falls through to a fresh run; JSON Schema verbatim, never Zod; `tool_result` text and image only; edits on the resuming turn ignored. [ADR 0001](../../docs/adr/0001-client-tools-through-a-held-open-run.md); four glossary terms added.
- [Conversation state and system prompt](issues/10-conversation-state-and-system-prompt.md): **continue the upstream session** when the normalised history fingerprints to one the wrapper has served and the tail is one user message (`--resume`, new run per turn, held open only while parked); otherwise a **replayed turn** renders the history into one stream-json user message with a self-describing `<conversation_history>` block. System prompt is **replaced** with exactly the client's `system` (empty when absent, `--system-prompt-snapshot off`); `--setting-sources=` and a wrapper-owned empty cwd; stream-json in and out via `spawn`; same-role merge, prefill/empty/system-role 400s, `cache_control` and thinking accepted and ignored; base64 images supported, `url` images and `document` blocks conditional on ticket 18, else 400 naming the block; no Anthropic-side wrapper sessions, `metadata.user_id` ignored. [ADR 0002](../../docs/adr/0002-conversations-continue-an-upstream-session-by-fingerprint.md); three glossary terms added. Process lifecycle graduated to ticket 19; probe batch 16, 17, 18 released.
- [MCP tool name limits upstream](issues/17-mcp-tool-name-limits-upstream.md): upstream neither truncates, aliases nor rejects long MCP tool names; the API's 128-character limit applies to the prefixed name and `mcp__client__` is 13 characters, so the surface validates `tools[].name` against `^[a-zA-Z0-9_-]{1,115}$` and 400s 116 to 128 before spawning. Hyphens and long shared prefixes need nothing. Findings in `research/mcp-tool-name-limits-upstream.md`.
- [Minimal-context upstream run](issues/16-minimal-context-upstream-run.md): with the decided flags, `--system-prompt ""` on the raw CLI sends **493 input tokens** per run (about $0.012), uncached; `"You are a helpful assistant."` 503; `--safe-mode` and `--disable-slash-commands` add nothing; `--system-prompt-snapshot off` costs nothing and is what makes new system text apply on `--resume` (default `on` ignores it); `--bare` is refused on the OAuth login with no API call. The spike's 9.8k/2.1k were two-call sums (first calls 4,836 raw, 1,015 SDK), so the system-prompt cost no longer separates the drivers. **Residual context, fact:** the CLI prepends "You are a Claude agent, built on Anthropic's Claude Agent SDK." to any `--system-prompt` and injects six `<system-reminder>` blocks into the first user turn (environment, model identity, token budget, USD budget, date, and the **account owner's email**); the model self-identifies as Claude built on the Agent SDK, never as Claude Code. Suppression and disclosure are the new unfired research ticket [Residual upstream context and the account-email reminder](issues/20-residual-upstream-context-and-account-email.md). Findings in `research/minimal-context-upstream-run.md`.
- [Image and document block pass-through upstream](issues/18-image-and-document-pass-through-upstream.md): through stream-json input upstream forwards `document` blocks with `base64` PDF, `text` and `content` sources, plus `title`, `context` and `citations` (the citation arrives only as a `stream_event` `citations_delta`), alongside `image`/`base64`: all supported under Conversation state decision 9. `image`/`url` and `document`/`url` are forwarded but the API answers `400 Unable to download the file` on every host, so they are a surface 400 naming the block type. Side facts: an API 400 does not end a held-open run, its `result` is `subtype: success` with `is_error: true` and `api_error_status: 400`, and the rejected user message stays in upstream's history. Findings in `research/image-and-document-pass-through.md`.
- [Web search and built-in tools policy](issues/08-web-search-and-built-in-tools-policy.md): `web_search_*` maps to built-in WebSearch and is **synthesised as the API's blocks** (`server_tool_use` with upstream's `srvtoolu_` id, `web_search_tool_result` with url/title items and a wrapper-minted opaque `encrypted_content`, no citations); `web_fetch_*` maps to WebFetch best effort, lossiness documented; `max_uses` and domain lists enforced by a `PreToolUse` hook (`updatedInput`, deny), `user_location` ignored; `--tools ""` unless a server tool is declared, `--permission-mode default --permission-prompts none` with an exact `--allowedTools`; `tool_choice: none` disables server tools too; usage counts from `searchCount`; block order fixed for Streaming; other server-tool types 400. No ADR. New research ticket 21 (hook enforcement) fired with 20.
- [Residual upstream context and the account-email reminder](issues/20-residual-upstream-context-and-account-email.md): **not suppressible on the subscription login.** `CLAUDE_CODE_SIMPLE=1` refuses the login like `--bare`; `--exclude-dynamic-system-prompt-sections` is ignored with `--system-prompt`; `CLAUDE_CODE_DISABLE_ATTACHMENTS=1` drops only the token and budget reminders; `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` changes nothing and **silently switches the model to Opus 5.5**. Without an instruction the model quotes the account email on a direct ask (4 of 4 runs); with a "never disclose" system prompt it refused (1 run). Whether the wrapper adds such an instruction itself is the new grilling ticket [Mitigating the account-email disclosure](issues/22-mitigating-the-account-email-disclosure.md). Findings in `research/residual-upstream-context.md`.
- [Hook enforcement of web tool limits upstream](issues/21-hook-enforcement-of-web-tool-limits-upstream.md): **verified on both drivers.** A `PreToolUse` hook passed as `--settings` inline JSON fires on a `-p --setting-sources=` run (and in-process through the SDK's `hooks` option); `updatedInput` applies `allowed_domains` and `blocked_domains` to WebSearch without the model noticing (10/10 and 0/N hosts); a deny reaches the model as a `tool_result` with `is_error: true` and text `PreToolUse:<tool> hook error: <reason>`, is listed in `result.permission_denials`, costs no side call, and the run continues; WebFetch behaves the same and `WebFetch(domain:*)` under `default` + `none` fetches without a prompt. Findings in `research/hook-enforcement-of-web-tool-limits.md`.
- [Streaming fidelity](issues/09-streaming-fidelity.md): **passthrough**, one translator feeding both the SSE sink and the non-streaming accumulator; a turn is one *turn stream* flattened across upstream's *model calls* (first `message_start` kept, indices offset, a call's `message_delta`/`message_stop` suppressed when all its tool calls are built-in; park when any is `mcp__client__`); client `tool_use` held behind a preceding built-in's result; server-tool input filtered to `{query}`/`{url}` in one delta; thinking relayed empty; usage = field-wise sum of per-call usage (= `result.usage`, measured) so the response closes at `message_stop`; allowlist field hygiene; HTTP status committed at first `message_start` (pre-commit failures are HTTP statuses, post-commit one SSE `error` then interrupt and forget the session); upstream retry loop capped at 60 s; idle `ping` every 15 s; mid-stream disconnect interrupts and forgets the session. All checked against the SDK minimums. [ADR 0003](../../docs/adr/0003-responses-assembled-from-stream-events-flattened-across-model-calls.md); two glossary terms. Ticket 13 unblocked.
- [Model and parameter mapping](issues/11-model-and-parameter-mapping.md): a wrapper-shipped **catalogue** (ids, aliases, `ModelInfo` limits) is the model universe: unknown names 404 before any spawn, the canonical id goes to `--model`, `message.model` relays upstream's resolved id; `GET /v1/models` serves the Anthropic shape when `anthropic-version` is present and today's OpenAI handler otherwise; `max_tokens` is honoured through `CLAUDE_CODE_MAX_OUTPUT_TOKENS` with the turn cut at the first `max_tokens` stop, `stop_sequences` emulated in the translator, both followed by interrupt-and-forget (upstream otherwise auto-continues past its cap); `temperature`/`top_p`/`top_k` non-defaults 400 on every model; `thinking` and `output_config.effort` validated against the catalogue (`adaptive` only on 5.x; Haiku gets `CLAUDE_CODE_DISABLE_THINKING=1` or `MAX_THINKING_TOKENS`); `output_config.format` maps to `--json-schema` with the `StructuredOutput` call rendered as the JSON text block; `count_tokens` measures with a one-token capped run; run-bound parameters on a resuming turn are ignored; unknown and beta-only fields and `container` 400, `service_tier`/`inference_geo`/`diagnostics` ignored; never `--fallback-model` or `--max-budget-usd`; `<synthetic>` assistant frames dropped. Checked against the SDK minimums. [ADR 0004](../../docs/adr/0004-output-limits-emulated-by-cutting-the-turn-stream.md); two glossary terms.
- [Error envelope and auth headers](issues/12-error-envelope-and-auth.md): a **surface tag** (path under `/v1/messages`, or `anthropic-version` present) selects the Anthropic envelope `{type: "error", error: {type, message}, request_id}` plus a `request-id` header in the shared handler, JSON-parse branch and auth middleware; `anthropic-version` required on `/v1/messages*` (`2023-06-01`, `2023-01-01`); the wrapper's optional key accepted as `x-api-key` or Bearer, never forwarded upstream; `anthropic-beta` ignored except what ticket 15 consumes; 32 MB body limit with 413; upstream failures map by **what the client should do**: API 4xx relayed with the API's own message, `rate_limit`/`overloaded`/5xx as 429/529/500 for retry, and upstream login or billing failures as 500 `api_error` with `x-should-retry: false` (never 401/402, the client's key was fine); deterministic `api_retry` categories interrupt at first sight; the billing-gate 400 relayed verbatim and never retried; `retry-after` from `rate_limit_event.resetsAt`, no fabricated `anthropic-ratelimit-*` headers; `req_` ids on every response and in SSE `error` data; the OpenAI surface's error classes untouched. Checked against what the SDKs read. [ADR 0005](../../docs/adr/0005-operator-side-upstream-failures-surface-as-500.md); one glossary term.
- [Module layout and seams](issues/13-module-layout-and-seams.md): **raw CLI driver** (`spawn`, stream-json, `@modelcontextprotocol/sdk` the only new runtime dependency, no Agent SDK); two new directories, `app/src/upstream/` (surface-neutral: typed frames, runner `startRun(spec) → Run` with `SpawnRunner` and `ReplayRunner` adapters, loopback **control server** hosting the bridge's MCP endpoint and the hook endpoint per run, the bridge state machine lifted from the spike, the scheduler ticket 19 will fill) and `app/src/anthropic/` (surface: `planTurn` on the request side, catalogue, pure translator with control signals inline, SSE sink and accumulator, sessions, one conductor, composition root); the OpenAI surface untouched beyond five wiring points in `server.ts`; `/v1/models` negotiated by mounting order; a static OpenAPI document for the surface; tests in three layers with the official SDK as a devDependency driving the integration suite and the real CLI behind a flag for e2e; the test-strategy fog graduated here with its e2e scenario list. Module map and interface table on the ticket. [ADR 0006](../../docs/adr/0006-raw-cli-driver-over-the-agent-sdk.md); one glossary term.
- [MCP connector passthrough](issues/15-mcp-connector-passthrough.md): **honoured, opt-in per deployment** (an operator host list, default off, because upstream connects from the operator's machine), beta-gated like the real API (`mcp-client-2025-11-20`, else 400 extra inputs); the real API's validation rules mirrored plus a 400 for a connector named `client`; each server one `--mcp-config` `http` entry in the per-run `0600` file with the Bearer token, `alwaysLoad: true`, a 60 s per-server call timeout, `--allowedTools mcp__<name>` or per-tool; `defer_loading` and per-tool `configs` ignored (no tool search with `--tools ""`); every server must be `connected` in `system/init` or the turn fails pre-commit; the translator synthesises `mcp_tool_use`/`mcp_tool_result` from upstream's `mcp__<server>__<tool>` frames like server-tool blocks, no park; the renderer gains the two block kinds; `count_tokens` mounts connectors too; tokens redacted and removed at teardown. - [Process lifecycle and concurrency](issues/19-process-lifecycle-and-concurrency.md): three per-run timers (startup 20 s, **stall 90 s on frame silence**, active lifetime 30 min excluding park) answering 504 `timeout_error`; one cap on runs in existence (default 4, parked included, never evicted) answering 529 at once with no queue, plus 429-with-`retry-after` admission from upstream's last `rate_limit_event`; a mutex per upstream session with a 10 s wait for the previous run's exit then SIGKILL, duplicates re-planned; one teardown ladder (interrupt → result 5 s → stdin close → exit 2 s → SIGTERM 5 s → SIGKILL) for every early end; shutdown drains in 15 s with 529 for newcomers and an SSE `error` for streams; line-streamed stdout with a 16 MB line cap, 64 KB stderr ring, no stdin cap; one fixed empty cwd so all transcripts share one project directory, per-run `0600` files under `<state>/runs/<id>/`, orphans deleted at start, hourly sweep, map capacity 1,000; child environment = base allowlist + always-set knobs + an operator `upstream.env` map for credentials, never inherited `CLAUDE*`/`ANTHROPIC*`; `--max-turns 25`; scheduler counts on `/health`. ## Out of scope

- Replacing or removing the OpenAI surface; the brief says "also".
- Reworking the OpenAI surface's prompt-template approach. If a shared upstream runner falls out of this spec, migrating the OpenAI surface onto it is a separate effort.
- Message Batches, Files API, Admin API, Managed Agents, Agent Skills, prompt-caching semantics (`cache_control` is accepted and ignored). None of these have an upstream equivalent in a CLI run.
- Implementing the spec. The map ends at a locked spec; `/to-tickets` and `/implement-spec` take over from there.
- **Agent mode**: letting a request run Claude Code's file and shell tools on the host. Ruled out of the first spec in [Destination and target clients](issues/01-destination-and-target-clients.md); the surface is a pure model endpoint. If wanted later, it is an opt-in server flag and a fresh effort.
